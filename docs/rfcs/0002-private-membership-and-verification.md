# RFC 0002：私有群 Wiki 的账号、权限与手机／邮箱验证码

- 状态：按最终邮箱单渠道范围实施并验收；见实现记录。
- 日期：2026-10-24。
- 前置：[RFC 0001](0001-lightweight-wiki-go-vue.md)。文章 + Tag、Go 承接 Vue、SQLite 单实例保持不变。
- 已确认：手机与邮箱都要支持；正式网站必须登录后才能查看。后续费用比较后，用户最终确认个人项目使用 PNVS 平台短信按量发送、不买套餐，并要求严格限量。
- 保密边界：公开文档仅记录配置项和占位示例。实际 CLI profile、发信地址、域名、密钥、资源查询结果及服务器记录只保存在 Git 忽略的本地私有目录或服务器秘密配置中。

## 最终范围修订（优先于下文原双渠道设计）

用户最终决定暂不使用手机号和短信，只使用邮箱。当前交付范围为邮箱邀请加入、验证码登录、绑定／更换、重新验证、已有密码登录、三级角色、私有阅读及媒体。Go 正式启动只要求邮箱配置及身份加密密钥；页面不提供手机号入口，运行身份移除短信发送权限，无短信资源包或 PNVS 开通需求。

B03 手机真实投递移出本次验收；B05、B06、B07、B12、B13 按邮箱单渠道执行。B13 桌面和 360px 页面自动化验收，实际手机输入法体验留作发布前设备验收。下文手机与双渠道描述保留为早期方案记录，不构成当前启用功能。当前配置以 `config/wiki.env.example` 和运行说明为准。

## 1. 建议直接采用的方案

| 项目 | 本轮方案 |
| --- | --- |
| 加入方式 | 邀请制；拥有手机或邮箱不代表自动获得群 Wiki 访问权 |
| 登录方式 | 手机验证码、邮箱验证码均可；已有用户名密码继续使用 |
| 绑定规则 | 每个账号最多绑定一个已验证手机号、一个已验证邮箱；可以只绑定其中一个，也可以两者都绑定 |
| 手机发送 | 阿里云号码认证服务 PNVS，使用平台签名和配套验证码模板，不申请自定义签名 |
| 邮件发送 | 阿里云邮件推送 DirectMail 的 SMTP，优先 TLS 465；为 Wiki 配置独立发信地址和 SMTP 密码 |
| 验证码 | Go 统一生成并核验；短信和邮件共用同一套挑战、限流和一次性消费逻辑 |
| 角色 | 系统管理员、管理员、普通用户；普通用户默认可共同编辑，可单独设为只读 |
| 内容访问 | 正式模式强制登录；移除公开阅读开关及匿名例外 |
| 运维配置 | 独立配置文件／环境变量，由 Go 服务读取；管理页面只显示渠道是否就绪及脱敏状态 |
| 资源 | 沿用单 Go 进程和 SQLite，无需 Redis、独立认证服务或消息队列 |

不要求每位群友同时验证手机和邮箱。两个渠道必须都可以使用，个人选择不等于系统缺少其中一个渠道。微信绑定和原生小程序仍是后续能力，复用同一个用户 ID 和身份表。

## 2. 页面效果

沿用已有的白底、深灰正文、玫红操作和简洁导航。登录页不显示人物名称、最近文章、Tag 数量、摘要或背景照片；没有公开文章预览或“游客浏览”。

### 2.1 登录与邀请加入

```text
+-------------------------------------------------------+
| 鸟托邦 Wiki                                            |
|                                                       |
|                 先登录，再看看群里的故事                  |
|                                                       |
|           [ 手机验证码 ]  [ 邮箱验证码 ]                 |
|           手机号 / 邮箱  [________________]             |
|           验证码         [______] [获取验证码]           |
```

切换渠道清空验证码和当前挑战，不沿用另一渠道的验证状态。重新发送展示 60 秒倒计时；倒计时只辅助交互，服务端负责实际限制。渠道故障保留当前输入，提供另一个渠道入口，不自动发送到其他地址。

邀请页先检查邀请是否有效，验证一种联系方式，再设置昵称并加入。邀请默认赋予普通用户，不能通过修改 URL 或请求参数得到管理员身份。邀请链接是短期秘密，不进入第三方分析、外链或 Referer；页面不加载第三方资源，读取邀请后清理地址栏中的凭证。

## 3. 角色与权限

后端使用 `system_admin`、`admin`、`user`。`can_edit` 只用于普通用户的只读限制，不新增一套可配置权限平台。管理员和系统管理员具有编辑能力。

| 操作 | 普通用户 | 管理员 | 系统管理员 |
| --- | --- | --- | --- |
| 阅读、搜索、时间线、引用、已发布历史 | 是 | 是 | 是 |
| 写作、上传、Tag、版本恢复 | `can_edit=true` 时 | 是 | 是 |
| 查看他人私有草稿 | 否 | 否 | 否；服务器级备份另受限制 |
| 编辑自己的账号与绑定 | 是 | 是 | 是 |
| 邀请普通用户 | 否 | 是 | 是 |
| 禁用／恢复普通用户，设置只读 | 否 | 是；禁止操作自身及更高角色 | 是 |
| 授予／撤销管理员及系统管理员 | 否 | 否 | 是，需近期重新验证 |
| 完整备份、成员安全操作审计、系统状态 | 否 | 否 | 是，备份需近期重新验证 |
| 修改发送凭证或开放匿名访问 | 否 | 否 | 无网页入口；匿名访问不支持 |

成员权限变更立即影响后续请求，禁用用户、变更绑定或密码后撤销相关会话。管理员降级撤销其全部会话。系统始终至少保留一个未禁用、具有实际登录凭证的系统管理员；检查与更新在同一事务中完成。

旧站导入的署名记录不是自动激活账号，不能仅凭同名或邮箱字符串认领其内容身份。历史作者信息继续保留，认领另行核实。

## 4. 全站强制登录的范围

当前实现已有 `public_read` 配置及演示匿名阅读，本 RFC 批准实施后正式模式删除这条放行路径。旧数据库即使 `public_read=true`，升级后也不能继续匿名访问。

| 请求类别 | 未登录行为 |
| --- | --- |
| 首页、Tag、文章、搜索、时间线、历史、引用、草稿、管理 | 网页导航到登录页；API 返回 401，不返回任何业务数据 |
| 图片、缩略图、视频 Range、媒体下载 | 每次验证登录和可读性；原始 OSS 对象保持私有 |
| Vue JS/CSS、站标、登录界面 | 可下载，不内嵌实际内容或成员资料 |
| 会话状态、登录、邀请检查／加入、必要的验证码接口 | 最小匿名白名单，分别执行用途、邀请和频控校验 |
| 健康与就绪探针 | 仅最小状态，不含成员、数据库路径或配置 |

前端路由守卫改善体验，不能代替 Go 鉴权。授权必须覆盖 HEAD、Range、历史媒体、导出、随机文章、全文搜索、旧站重定向后的目标接口等所有入口；匿名不能通过已知文章 ID 判断文章是否存在。

业务与认证响应统一 `Cache-Control: private, no-store`；CDN 不缓存 `/api`、媒体及含身份的响应。仅哈希静态资源允许公共缓存。网页媒体通过同源 Go 鉴权代理流式输出；不把可转发的 OSS 下载签名地址当成永久媒体 URL。上传仍可使用受限的短期 OSS PUT 签名。

退出／会话失效后清空前端正文、列表及草稿缓存；浏览器返回或从后台恢复时重新确认会话。已经合法下载的文件无法远程收回，所谓“必须登录”约束的是新请求和站内访问，不承诺撤销用户已保存的副本。

登录后的 `return_to` 只允许站内相对路径；不把文章内容拼入登录页。邀请凭证不保留在回跳地址中。开发演示必须使用独立数据且仅监听回环地址；正式模式不得开启演示登录。

## 5. 登录、加入与绑定

```text
手机／邮箱输入
      |
      v
检查用途 + 会话／邀请 + 限流 + 渠道就绪
      |
      v
创建一次性挑战，预占发送额度（SQLite 事务）
      |
      v
Go 生成验证码 -> PNVS 平台短信 / SMTP 邮件
      |
      v
用户提交 challenge_id + 验证码
      |
      v
核验期限、次数、渠道、目标、用途、会话及账号状态
      |
      +---- 登录 -> 已有有效成员 -> 新会话
      +---- 加入 -> 有效邀请 -> 原子消费邀请并创建账号
      +---- 绑定 -> 当前账号 -> 原子占用唯一联系方式
```

### 5.1 登录与邀请

- 验证码登录只查找已验证的身份；未知地址、禁用账号和未加入的地址不自动注册，不泄露账号是否存在。
- 发送接口对地址是否注册使用相同的受理提示与不透明挑战 ID；无效目标可以不实际发送。验证失败统一提示，不声称通道故障时“已经送达”。渠道整体不可用可公开提示，并建议使用另一渠道。
- 加入需要有效邀请与一个联系方式的验证码；加入事务同时验证邀请未过期／未撤销、身份尚未占用，消费挑战和邀请，创建用户及身份。
- 同一手机号或邮箱已属于其他账号时不自动合并，不转移文章或权限；提示该联系方式无法绑定。先登录已有账号，再联系系统管理员核实处理。
- 原用户名密码继续可用；新用户可在登录后设置密码。系统管理员必须保留密码作为独立登录途径，避免任一发送渠道故障锁住管理入口。

### 5.2 绑定、更换与找回

普通首次绑定需要有效会话与该地址验证码。更换或解除既有绑定、设置／修改密码、授予角色、下载完整备份需要最近 5 分钟内重新验证本人。更换绑定必须验证已有凭证和新联系方式；仅持有新号码不能替换旧号码。

近期验证可以使用已有密码或已绑定的其他渠道；验证码证明绑定在“账号 + 具体用途 + 本次会话”，不能跨用途使用。解绑至少保留一种可用登录方法。系统管理员的敏感操作重新验证必须使用密码；后续可增加专用 MFA，本轮不把短信称作抗钓鱼认证。

普通用户和管理员验证已绑定联系方式可执行找回流程，但仍检查成员是否被禁用；成功后撤销旧会话。系统管理员不允许单凭一个手机或邮箱码重置管理密码，丢失密码须使用服务器本地恢复流程，记录审计并撤销会话。两个渠道都丢失且无密码的用户走管理员人工核实，不按昵称、文章署名或新邮箱自动恢复。管理员不能查看原验证码，也不能直接改填一个新联系方式让其变成已验证。

## 6. 手机发送：确定采用 PNVS 平台方案

使用 `dypnsapi.aliyuncs.com` 的 `SendSmsVerifyCode`，API 版本 `2017-05-25`。国内手机先支持 `+86`，展示时脱敏；不默认支持国际号码。平台签名和平台模板必须配套使用；它们与传统短信服务 `dysmsapi` 的自定义签名、`SMS_...` 模板及套餐不同，不能混用。[短信认证指引](https://help.aliyun.com/zh/pnvs/getting-started/sms-authentication-service-novice-guide)、[个人开发者接入说明](https://help.aliyun.com/zh/pnvs/use-cases/sms-verify-for-individual-developers)

“默认平台签名”表示在服务端配置一组当前可用的平台签名与模板，不表示省略必填 `SignName` 和 `TemplateCode`，也不把文档示例签名硬编码成账号已可用资源。首次部署确认功能开通及配套参数，再保存到私有配置。

为让邮箱与手机使用同一套用途隔离及一次性消费逻辑，验证码由 Go 的 `crypto/rand` 生成 6 位数字，通过模板变量发送。PNVS 请求关键字段：

| 字段 | 设置 |
| --- | --- |
| `PhoneNumber`、`CountryCode` | 规范化后的国内号码、`86` |
| `SignName`、`TemplateCode` | 私有配置中的平台签名／配套模板 |
| `SchemeName` | Wiki 专用稳定场景名，与其他应用隔离；不含个人信息 |
| `TemplateParam` | `code` 为本次验证码，`min` 为 `5`；变量名与所选模板一致 |
| `ValidTime`、`Interval`、`DuplicatePolicy` | 300 秒、60 秒、覆盖旧码 |
| `ReturnVerifyCode` | 显式 `false` |
| `OutId` | 无个人信息的挑战关联 ID |

官方接口允许指定验证码；自定义验证码不由 `CheckSmsVerifyCode` 核验。因此本方案不调用云端核验接口，Go 负责验证、次数限制及原子消费；有效期与应用提示同步。不同时引入第二套托管核验状态。[发送参数](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)、[核验限制](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)

部署前仍需确认号码认证功能开通、付费状态、平台配套参数和 RAM 权限；不因其他阿里云服务可用而推断本服务已开通。不执行付费试发或购买套餐来“检查是否可用”。后续只向明确指定的测试号码试发。

## 7. 邮件发送与参考项目的复用边界

已参考相邻服务的 Go 配置结构、SMTP 抽象、TLS 465／STARTTLS 连接及京东云部署配置习惯。复用模式，不复制其业务内容、收件人、SMTP 密码或真实域名。该服务使用邮件验证链接，本项目按本次需求发送数字验证码。

Wiki 配置独立的 DirectMail 触发类发信地址和 SMTP 密码，可沿用同一个云服务商，不依赖应用主机也在阿里云。Go 连接配置地域对应的 SMTP 端点，优先 TLS 465；不允许明文认证或 TLS 证书校验失败后降级。SMTP 密码与阿里云 AccessKey 是不同的凭证。[SMTP 接入](https://help.aliyun.com/zh/direct-mail/user-guide/send-emails-using-smtp)、[地域端点](https://help.aliyun.com/en/direct-mail/smtp-endpoints)

邮件包括站名、验证码、用途、5 分钟有效期和“非本人操作可忽略”，同时提供纯文本与 HTML。没有原始文章、群友个人资料、营销内容或第三方跟踪像素。模板参数转义，邮件主题及地址拒绝 CR/LF。

供应商接收不等于用户已收到；失败不标记为已验证。首次部署检查发信身份、域名验证和投递配置，再分别验证常用邮箱的收件与垃圾箱情况。不能以 SMTP TCP 端口可连接代替真实投递验收。

## 8. 配置与秘密管理

Go 增加显式 `--env-file /etc/wiki/wiki.env`，优先级为进程环境变量 > 指定文件 > 安全默认值。参照现有项目配置习惯，使用 systemd `EnvironmentFile` 或容器 `env_file` 注入也可；不隐式遍历父目录寻找其他项目的 `.env`。源码只保留占位模板，不把本机 CLI profile 当成生产身份。

| 配置项 | 用途／初值 |
| --- | --- |
| `BASE_URL` | 正式站点 HTTPS 源地址 |
| `AUTH_REGISTRATION_MODE` | 固定 `invite_only`，本轮不提供开放注册 |
| `AUTH_SECRET_FILE` | 32 字节随机主密钥的私有文件；不能使用示例密码或提交仓库 |
| `AUTH_CODE_TTL_SECONDS` | `300` |
| `AUTH_CODE_RESEND_SECONDS` | `60` |
| `AUTH_CODE_MAX_ATTEMPTS` | `5` |
| `AUTH_SEND_PER_TARGET_HOUR`／`DAY` | `5`／`10`，同目标跨用途累计 |
| `AUTH_SEND_PER_IP_HOUR` | `30`，代理地址仅信任显式配置的代理网段 |
| `AUTH_SMS_DAILY_LIMIT`／`AUTH_EMAIL_DAILY_LIMIT` | 短信 `20`、邮件 `100`，站点级硬上限 |
| `AUTH_SMS_MONTHLY_LIMIT` | `100`，UTC 自然月内短信受理尝试硬上限，跨重启保留 |
| `SMS_PROVIDER` | `aliyun_pnvs` |
| `SMS_REGION`／`SMS_ENDPOINT` | 与所选服务相符；端点固定服务端白名单，不接受浏览器指定 |
| `SMS_SIGN_NAME`／`SMS_TEMPLATE_CODE`／`SMS_SCHEME_NAME` | 平台配套参数及 Wiki 场景，均为服务端配置 |
| `SMS_ACCESS_KEY_ID`／`SMS_ACCESS_KEY_SECRET`／`SMS_SECURITY_TOKEN` | Wiki 专用最小权限发送身份；可注入临时 STS 凭证，当前版本不自动刷新，轮换后需重启加载 |
| `SMTP_HOST`／`SMTP_PORT`／`SMTP_TLS_MODE` | 地域 SMTP 端点、`465`、`implicit_tls` |
| `SMTP_USER`／`SMTP_PASSWORD`／`SMTP_FROM` | Wiki 专用发信身份和秘密 |
| `SMTP_CONNECT_TIMEOUT_SECONDS`／`SMTP_SEND_TIMEOUT_SECONDS` | `5`／`10`，覆盖 TLS、认证与正文发送 |
| `AUTH_SESSION_DAYS`／`AUTH_REAUTH_SECONDS` | `30`／`300` |
| `TRUSTED_PROXY_CIDRS` | 默认空；仅配置实际反向代理范围 |

生产要求手机和邮件两个渠道均完整配置；配置缺失、演示发送器或不合法 TTL 直接报错，不以 no-op 假装成功。状态页区分“配置完整”“最近发送受理”“真实投递已验证”。运行时某一服务故障不导致整个 Wiki 退出，保留另一渠道及已有密码登录。

服务器配置目录建议 `0700`，秘密文件 `0600`，仅服务用户可读。`AUTH_SECRET_FILE` 与数据库分开备份，用于派生联系方式加密、查询索引和验证码摘要所需的不同用途密钥；不能用一个无域隔离的摘要混用三种用途。已存在身份数据时若密钥缺失或不匹配，拒绝启动，不能自动生成新密钥掩盖数据损坏。密钥轮换必须显式迁移及恢复演练，第一阶段不提供网页轮换按钮。

生产部署使用最小 RAM 权限：本地核验方案运行时只需要 `dypns:SendSmsVerifyCode`，不授予 SMS 管理、资源开通、RAM 管理或 OSS 全权限；SMTP 使用独立密码。管理用 CLI profile 只用于部署核查，不随程序、镜像或配置模板分发。运行凭证不得与参考项目共享。

公开 `.env.example` 只允许占位值；真实文件及数据在 Git 和 Docker 两层排除。前端禁止使用 `VITE_*` 保存任何秘密。管理接口不返回完整配置，错误、日志、测试快照及 CI 输出不记录验证码、邀请凭证、Cookie、手机号明文或 SMTP/云密钥。

## 9. 数据结构与验证码边界

| 表／修改 | 最少字段 |
| --- | --- |
| `users` | 保留用户 ID、昵称、密码摘要；更新角色枚举，增加 `can_edit`；保留禁用状态 |
| `user_identities` | `id`、`user_id`、`kind`、加密后的规范地址、查询 HMAC、`verified_at`；`(kind, lookup_hash)` 唯一 |
| `auth_challenges` | 随机 ID、用途、渠道、目标摘要、主体／预登录会话、验证码 HMAC、期限、尝试次数、发送／消费状态 |
| `auth_rate_limits` | 目标／账号／IP／站点窗口、原子计数与到期时间，不存明文地址 |
| `auth_audit_events` | 操作者、事件、对象 ID、结果、时间和脱敏渠道；不存验证码或完整地址 |
| `sessions` | 增加创建时间、最近活动、重新验证时间及凭证版本，保持 token 仅存摘要 |
| `invites` | 增加创建人、撤销时间、消费人及用途；邀请不能授予特权角色 |

手机号按国内 E.164 规范化，邮箱 trim 并按本系统明确的大小写不敏感规则生成唯一索引；不按 Gmail 点号或加号规则自动合并不同邮箱。新身份必须验证后才能写入已绑定集合；更换时旧身份保留到新身份的最终事务成功。

验证码 HMAC 至少绑定挑战 ID、渠道、目标、用途和主体。6 位验证码不能使用普通 SHA256 后直接存库以抵抗离线枚举；主密钥不在数据库内。码只在生成与发送的短暂内存中出现，不保存明文邮件队列。

发送前预占额度与创建挑战在短事务内完成；调用供应商在事务外，最长 10 秒。全局发送并发上限 2，饱和直接返回稍后重试，不建立无界 goroutine／排队任务。供应商超时状态记为未知，不能立即换渠道或无限重试，额度不回滚以免绕过费用限制。

同一目标跨用途 60 秒最多发送一次；新挑战令旧挑战失效。无效／过期／消费挑战均不可验证；第五次错误即锁定，需要重新发送。验证码成功与最终登录／加入／绑定动作一起在 SQLite 事务中消费，并发只能成功一次，不发放跨接口可重复使用的“已验证”布尔值。每账号验证请求另设分钟级速率上限，IP 伪造不能绕过限流。

普通挑战到期后 24 小时清理，频控保留到窗口结束后 24 小时；审计建议保留 90 天。已绑定联系方式保留到解绑／账号清理，备份和恢复也视为敏感数据处理。小时清理有数量上限，沿用单实例定时任务。

## 10. API 草案

以下是本 RFC 的设计，不表示现有 OpenAPI 已实现这些接口；批准后再同步正式契约。

| API | 作用与边界 |
| --- | --- |
| `GET /api/v1/auth/options` | 仅返回登录渠道可用性、是否需要初始化，不返回成员或秘密 |
| `POST /api/v1/auth/challenges` | `{channel,purpose,target,invite?}`；服务端校验会话／邀请，返回不透明 `challenge_id`、倒计时 |
| `POST /api/v1/auth/login-code` | `{challenge_id,code}`；只登录已有有效成员 |
| `POST /api/v1/auth/join` | `{invite,challenge_id,code,nickname}`；原子创建用户、绑定、消费邀请 |
| `POST /api/v1/account/identities/bind` | 当前会话 + 新渠道挑战；不接受目标 `user_id` |
| `POST /api/v1/account/identities/replace` | 已有凭证重新验证 + 新渠道挑战；并发唯一约束 |
| `DELETE /api/v1/account/identities/{id}` | 本人身份、近期重新验证、剩余登录方式检查 |
| `POST /api/v1/account/reauth` | 已有密码／渠道挑战；更新当前会话的重新验证时间 |
| `PUT /api/v1/account/password` | 本人近期重新验证，设置／修改密码后撤销旧会话 |
| `POST /api/v1/auth/recover` | 仅已绑定渠道；成功后撤销旧会话，不恢复禁用账号 |
| `GET/DELETE /api/v1/account/sessions[/{id}]` | 仅本人，返回少量脱敏会话信息 |
| `GET/PATCH /api/v1/admin/members[/{id}]` | 分页查询及受角色边界限制的成员调整 |
| `GET /api/v1/system/auth-status` | 仅系统管理员看脱敏配置和运行状态 |

已有密码登录、退出、邀请接口保持可迁移；修改类 Cookie 请求继续校验 CSRF 与 Origin。验证码提交不放 URL；预登录挑战绑定同源预认证 Cookie 并检查 Origin。整个授权校验由 Go 完成，不信任客户端自报角色、已验证状态或 IP。

`purpose` 固定枚举：`login`、`join`、`bind`、`replace`、`reauth`、`recover`；不得用于任意短信正文或群发。业务验证码发送接口不能成为公共消息网关。429 返回可用的重试等待时间，服务商原始错误与响应不直接传给浏览器。

## 11. 升级与实施顺序

1. **权限与私有访问**：新增角色与迁移，移除匿名内容开关，媒体改为每次鉴权，增加回归测试。完成后即便发送模块尚未接通，旧密码登录仍可用。
2. **统一验证码与绑定**：SQLite 挑战、限流、身份、审计；先用只在测试内可用的假发送器验证竞态和失效。正式配置不能启用假发送器。
3. **接通 SMTP 和 PNVS**：独立配置、超时、脱敏、限额；私有部署资料管理，确认开通及平台参数；向指定测试手机号／邮箱各验证一次投递与绑定。
4. **Vue 页面**：登录双渠道、邀请加入、账号绑定、重新验证、成员管理，手机宽度验收。
5. **迁移、备份与恢复演练**：账号身份与主密钥分别恢复，再做匿名访问、权限提升和历史数据回归。

迁移不根据显示昵称推断所有者。新初始化时创建首位系统管理员；现有库由服务端 CLI 显式指定现有可登录管理员 ID 为首位系统管理员，升级前检查该人有可用密码。未完成此预检不开放升级后的服务。其余原 `admin` 迁为管理员，原 `editor` 迁为 `user(can_edit=true)`，原 `viewer` 迁为 `user(can_edit=false)`，用户 ID、文章署名、密码摘要和版本不变。

角色／会话结构切换时撤销旧会话，要求重新登录。迁移前完成私有备份；迁移后新增绑定数据不得通过直接回滚旧程序或覆盖旧库丢弃。RFC 0001 的公开阅读和原最小角色方案在本 RFC 批准实施后由本方案替代。

初始规划阶段只做只读核查。后续经授权已创建专用媒体与发信资源并完成真实邮箱和媒体联调，未修改参考服务或购买短信套餐。实际资源清单单独存放私有目录。

## 12. 验收标准

| 编号 | 必须证明的行为 |
| --- | --- |
| B01 强制登录 | 匿名访问全部文章、Tag、搜索、历史、引用、媒体 HEAD／Range、导出均无内容；旧 `public_read=true` 不生效 |
| B02 三类身份 | 用户不可管理成员；管理员不可提升自己或操作更高角色；系统管理员不可删掉最后一个可登录同级账号 |
| B03 手机验证码 | 平台签名和配套模板真实发送到指定测试手机；输入正确码完成登录／绑定；错误码、旧码、过期码被拒绝 |
| B04 邮箱验证码 | 指定测试邮箱真实收到数字验证码；同样完成登录／绑定；SMTP 成功受理不冒充投递成功 |
| B05 用途隔离 | 登录码不可用于绑定；甲会话的绑定码不可用于乙；新手机码不能单独替换旧联系方式 |
| B06 邀请边界 | 知道任意有效手机号／邮箱不能自行入群；并发消费邀请仅成功一次；修改邀请码角色不能提权 |
| B07 唯一性 | 同手机号／邮箱并发绑定仅一个账号成功，其他账号信息不泄露、不自动合并 |
| B08 限流和费用 | 目标／IP／账号／站点限流实际生效，伪造代理头无效，重启不清空额度，超时不触发无界重试 |
| B09 会话撤销 | 禁用、密码／绑定变更、角色降级、退出后旧会话不能继续 API／媒体请求；网页缓存及时清空 |
| B10 配置与保密 | 凭证只在服务器，公开文档、测试、构建上下文、前端包和日志无真实秘密及验证码；缺失渠道不能假成功 |
| B11 旧库升级 | 旧用户、文章、作者和历史完整；原只读用户不被意外授予编辑；导入署名不被自动激活 |
| B12 失败与恢复 | 短信或 SMTP 中断仍能用其他现有方式登录；数据库及独立密钥恢复后身份与验证码状态正确 |
| B13 页面 | 桌面及 360px 下，双渠道登录、绑定、更换、重新验证均可操作；真机验证输入法与收信回填 |

本地自动化使用随机假身份、生成的媒体及模拟发送器，不接触实际手机号和云密钥。真实投递是独立部署验收，不能用 mock 测试代替。

## 13. 实施期间的费用约束补充

用户明确只需要短信验证码，希望费用低。比较普通短信与 PNVS 后，最终确定个人项目使用 PNVS 平台短信按量发送，不购买套餐，不接入一键登录／本机号码核验，不保留第二套发送实现。短信每天默认上限为 20 次，增加 `AUTH_SMS_MONTHLY_LIMIT=100`，按 UTC 自然月计数，限额按受理尝试计算以防超时重试造成费用绕过。

公开价格核查时，小用量普通验证码短信为 0.045 元/条，PNVS 短信认证 API 为 0.06 元/次；100 次分别约 4.50 元及 6 元，实际以供应商当期价格和账户账单为准。只使用 PNVS 短信验证码发送接口，不能因为产品归属名为号码认证就默认使用其他认证能力。[普通短信价格](https://help.aliyun.com/zh/sms/product-overview/notice-on-price-adjustment-for-domestic-sms-services-2604)、[PNVS 计费](https://help.aliyun.com/zh/pnvs/product-overview/product-pricing/)

## 邀请入口修订

注册仅由管理员生成的一次性链接进入，不展示“使用邀请加入”按钮或手填凭证框。创建时允许添加 200 字以内备注，管理员列表显示创建与消费记录；成功注册在事务中消费邀请，不能多人复用。数据库迁移 006 为旧邀请保留默认空备注与创建时间，不编造历史数据。
