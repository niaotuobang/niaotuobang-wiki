# RFC 0001 轻量群 Wiki 的页面与 Go Vue 架构

- 状态：主体方案进入本地实现，验证情况见[实现记录](../implementation-status.md)。
- 日期：2026-10-24。
- 实施状态：已提供 Go、Vue 与 SQLite 的本地版本；原 Next.js 源码暂留作迁移参考。AI 和原生小程序属于后续阶段。
- 适用范围：单个群体共同维护的 Wiki，优先网页，后续小程序复用后端。
- 资源边界：本文仅包含通用架构与示例；实际云账号、资源名称、域名、凭证及部署记录保存在本地忽略目录，不进入公开仓库。

## 1. 决策摘要

建设一个适合长期保存群友故事的轻量 Wiki。人工写下的小传、八卦、笑话、金句和事件经过是正文，网站通过 Tag、文章链接和发生时间组织内容。AI 后续辅助整理，保留作者的表达和出处。

产品只设置两个核心业务对象：**统一实体文章 Article** 和 **标签 Tag**。人物、事件、重大事件、结婚等都用 Tag 表示；不再引入独立的人物表、事件表、分类系统或可配置表单平台。

| 决策 | 方案 |
| --- | --- |
| 页面方向 | 参考 Matterwiki 的分类导航、文章列表和直接编辑体验，补齐中文、移动端、图文视频与时间线 |
| 文章 | 同一编辑器、同一存储结构，支持多个 Tag、可选发生时间和文章链接 |
| Tag | 每个 Tag 自动拥有列表页，是否进入侧栏导航单独控制 |
| 前端 | Vue 3、TypeScript、Vite；浏览器运行构建后的 JavaScript |
| 后端 | Go 模块化单体，提供业务 API、Vue 静态资源和后台任务 |
| 发布 | 前端构建产物通过 `go:embed` 嵌入 Go 程序，提供单文件与单容器两种发行方式 |
| 数据库 | 默认 SQLite，单实例运行，使用持久化本地磁盘 |
| 媒体 | 支持图片和视频；本地模式可直接使用，正式部署可配置阿里云 OSS |
| 部署位置 | Go 服务与 OSS 可以位于不同服务商；直传与播放使用可达的公网 HTTPS 地址 |
| 小程序 | 独立客户端，共用 Go API、账号和媒体数据；代码包由微信平台分发 |
| AI | 可选模块，后台处理、限额执行，结果作为待确认建议 |

Go 可以在编译时嵌入静态文件，Vite 可以生成静态托管所需的前端产物，因此正式运行不依赖 Node.js。[Go embed](https://pkg.go.dev/embed)、[Vite 构建文档](https://vite.dev/guide/build.html)

## 2. 产品边界

### 2.1 第一版要完成的闭环

```text
写文章 / 粘贴图片 / 上传视频
              |
              v
选择或创建 Tag，按需填写发生时间
              |
              v
保存草稿或发布文章
              |
       +------+------------------+
       |                         |
       v                         v
首页最近更新                 Tag 自动列表页
                                 |
                         +-------+-------+
                         |               |
                         v               v
                       列表            时间线
                         |
                         v
             阅读正文、点击引用、继续补充
```

第一版包含文章读写、图片视频、Tag 管理、列表与搜索、可选发生时间、内部文章链接与反向链接、草稿、版本历史，以及最小账号和权限体系。备份、恢复和旧内容迁移属于发布条件。

### 2.2 后续能力

- AI 推荐 Tag、文章链接和缺失的时间信息，展示依据并接受人工确认。
- 以原文为依据的问答、年度回顾、人物故事汇集。
- 明确的关系类型、局部关系图，以及可定位到历史段落的引用工具。
- 微信小程序阅读、搜索、分享、简单补充和上传媒体。
- 微信、手机号、邮箱登录及绑定。

第一版不实现微信群自动采集、实时多人光标协作、视频转码集群、多租户 SaaS、独立图数据库或通用自定义字段系统。这些能力不作为基础读写的运行依赖。

## 3. Matterwiki 参考与页面原则

参考对象为 **Matterwiki**。本项目借鉴其简单 Wiki 的交互理念，采用自己的品牌和实现。[Matterwiki 项目](https://github.com/Matterwiki/Matterwiki)

页面依据是本次提供的首页、列表与文章截图，以及项目公开文档；尚未完成旧站登录后的完整交互与数据核验。截图中的真实人物正文不进入公开示例，页面调试统一使用虚构内容。

| 参考体验 | 新版设计 |
| --- | --- |
| 左侧主题列表 | Tag 导航，显示名称和简短说明；过多 Tag 放入“全部标签” |
| 文章标题与更新时间列表 | 保留列表阅读方式，增加简短摘要、少量 Tag 和媒体标识 |
| 标题、正文、右侧编辑信息 | 正文占主要宽度，侧栏放 Tag、发生时间、编辑与历史入口 |
| 直接进入编辑 | 一个编辑器覆盖所有文章，不先选择人物或事件模板 |
| 文章历史 | 保存完整版本，能比较文字变化并恢复旧版 |
| 留白和少量强调色 | 白底、深灰文字、玫红链接与主要按钮，正文优先 |

首页使用内容列表，不使用统计仪表盘、虚构贡献人数或大面积宣传区。轻巧的趣味入口是“随便看看”和“时间线”；它们只从用户有权阅读的文章中取内容。

### 3.1 视觉约定

| 项目 | 初始设计值 |
| --- | --- |
| 页面底色 | `#FFFFFF` |
| 正文颜色 | `#34343B` |
| 次要信息 | `#686873` |
| 分隔线 | `#E6E6EB` |
| 主要强调色 | `#C91458`，用于链接、选中状态和主要按钮 |
| 浅色强调背景 | `#FFF1F6` |
| 字体 | 系统中文无衬线字体，优先 PingFang SC、Microsoft YaHei；不依赖远程字体 |
| 正文 | 桌面 17px，手机 16px；行高约 1.8；单段控制在舒适阅读宽度 |
| 标题 | 文章标题约 32–36px，列表标题约 20–22px，辅助信息 13–14px |
| 布局 | 左侧导航约 208px；正文约 720–800px；可选信息栏约 220px |
| 交互 | 明确的键盘焦点；移动触控目标至少 44px；遵循减少动态效果偏好 |

Tag 以轻量文字标签展示，颜色只作辅助，不作为唯一含义。文章列表不逐条加阴影卡片。图片按比例展示，长截图先显示有限高度，点击查看原图。视频显示封面和播放按钮，由用户主动播放。

## 4. 页面与路由

### 4.1 导航结构

| 路由 | 内容 |
| --- | --- |
| `/` | 最近更新，常用 Tag，写文章入口 |
| `/tags` | 所有 Tag，搜索 Tag；编辑者可新建 Tag |
| `/tags/:id` | Tag 列表页，支持列表／时间线切换 |
| `/articles/:id` | 统一文章详情页 |
| `/articles/new` | 新建文章 |
| `/articles/:id/edit` | 编辑文章 |
| `/articles/:id/history` | 版本列表、文字比较和恢复 |
| `/timeline` | 全站有发生时间的可读文章 |
| `/search?q=...` | 全文搜索，支持 Tag 筛选 |
| `/drafts` | 当前用户的草稿 |
| `/account` | 当前账号，后续扩展身份绑定 |
| `/admin` | 管理员配置、成员、Tag 导航、备份与用量 |

人物入口就是被放入导航的“人物”Tag；事件入口同理。路由以稳定 ID 定位，中文标题和 Tag 改名不会改变引用身份。保留可读标题不要求用标题生成唯一 slug。

### 4.2 首页

```text
+------------------------------------------------------------------+
| 鸟托邦 Wiki             搜索文章、人物、梗……        [写文章]  账号 |
+-------------+----------------------------------------------------+
| 最近更新    | 最近更新                           [按更新时间 v]  |
| 时间线      |                                                    |
| 随便看看    | 某次露营的故事                                     |
|             | 一段由群友写的摘要……                               |
| 常用标签    | [事件] [聚会]     发生于 2025-05    昨天由某人补充  |
|  人物       | -------------------------------------------------- |
|  事件       | 一个外号的来历                                     |
|  重大事件   | 另一个值得记下来的故事……                           |
|  金句       | [人物] [群梗]                       某人更新        |
|             |                                                    |
| 全部标签    | [加载更多]                                         |
| 我的草稿    |                                                    |
+-------------+----------------------------------------------------+
```

- 默认按文章最近一次发布更新排序；草稿自动保存不影响公开列表排序。
- 行内展示标题、最多两行摘要、最多三个 Tag，以及发生时间和更新信息。
- 图片和视频仅显示小缩略图或类型标识，不在列表加载原视频。
- 空站点显示“写下第一篇文章”；加载失败保留重试入口，不能伪装为空列表。
- 搜索框在所有主要页面保持同一位置。手机允许折叠为搜索按钮。

### 4.3 Tag 页

```text
+------------------------------------------------------------------+
| 鸟托邦 Wiki             搜索……                      [写文章]     |
+-------------+----------------------------------------------------+
| 最近更新    | 聚会                                      [编辑Tag]|
| 时间线      | 记录见面的那些事                                   |
|             |                                                    |
| 常用标签    | [列表] [时间线]         [增加筛选] [在此写文章]     |
|  人物       | -------------------------------------------------- |
|  聚会       | 文章标题 / 摘要 / 其他 Tag / 更新时间               |
|  金句       | 文章标题 / 摘要 / 其他 Tag / 更新时间               |
+-------------+----------------------------------------------------+
```

每个 Tag 自动有页面，不单独创建或维护“列表页”对象。Tag 可配置名称、说明、是否展示在导航和导航顺序。预置与自定义 Tag 使用相同权限和能力。

“在此写文章”只预选当前 Tag，作者仍可修改。多 Tag 筛选默认取交集，界面明确显示选中的标签。空 Tag 页可存在并邀请补充内容。

Tag 重命名保留 ID。删除 Tag 只移除关联，不删除文章；管理员先看到影响文章数量并确认。历史版本保留当时的标签名称快照。第一版不实现 Tag 层级和同义词自动合并。

恢复历史版本时，仍存在的 Tag 按 ID 还原；已删除的 Tag 显示为待处理项，不能静默重新创建。作者可选择忽略或明确新建同名 Tag。

### 4.4 文章详情

```text
+------------------------------------------------------------------+
| 鸟托邦 Wiki             搜索……                      [写文章]     |
+-------------+--------------------------------------+-------------+
| 最近更新    | 某次露营的故事                       | 关于这篇    |
| 时间线      | 更新于…… / 某人                      | [事件]      |
|             |                                      | [聚会]      |
| 常用标签    | 人工撰写的正文。                     | 发生于      |
|  人物       | 写到另一篇文章时可以直接链接。       | 2025-05     |
|  事件       |                                      |             |
|  金句       | [图片与说明]                         | [编辑]      |
|             |                                      | [历史版本]  |
|             | [视频封面] [播放]                    |             |
|             |                                      |             |
|             | 提到本文的文章                       |             |
|             | · 另一篇文章及附近原文               |             |
+-------------+--------------------------------------+-------------+
```

正文使用统一渲染器，人物文章不自动生成额外表单或评分。正文中的内部链接有可识别样式；桌面可显示简短预览，手机点击进入详情。返回时恢复上一个列表的筛选和滚动位置。

第一版“提到本文”只来自已保存的明确内部链接，保留上下文并按权限过滤，不将共同 Tag 解释为人物关系。引用型正文块先支持原文与来源链接；精确历史段落引用工具在后续增加，底层提前保留段落 ID。

无阅读权限、草稿和回收站文章不通过标题、摘要、Tag 数量或反向链接泄露内容。默认群成员可读，公开站点模式由管理员显式开启。

### 4.5 编辑器

```text
+------------------------------------------------------------------+
| 返回文章             草稿已保存                 [预览] [发布]    |
+------------------------------------------------------------------+
| 标题                                                             |
| 输入文章标题……                                                   |
|                                                                  |
| Tag   [聚会 x] [事件 x] [+ 添加或创建]                             |
| 发生时间（可选） [年 / 月 / 日]   精度 [日 v]                     |
|                                                                  |
| [标题] [加粗] [列表] [引用] [链接文章] [图片] [视频] [撤销]        |
| ---------------------------------------------------------------- |
| 开始写下这个故事……                                               |
|                                                                  |
| 图片上传：进度 / 重试 / 取消                                      |
| 视频上传：进度 / 重试 / 取消                                      |
|                                                                  |
| 本次修改说明（可选）                                             |
+------------------------------------------------------------------+
```

- 标题与非空正文是发布必填项，Tag 和发生时间可留空；草稿允许未完成内容。
- 输入 Tag 名称先搜索已有项，没有匹配项时明确显示“创建 Tag”。
- 编辑器采用 Tiptap 的 Vue 集成和受控节点集合：段落、标题、列表、引用、图片、视频、外部链接及内部文章链接。[Tiptap Vue 集成](https://tiptap.dev/docs/editor/getting-started/install/vue3)
- 支持选择文件、拖入和粘贴图片；图片附说明，视频显示上传状态与播放能力。
- 上传中的媒体不能作为已完成媒体发布。可以保存文字草稿，待上传完成再发布。
- 草稿防抖自动保存，发布才生成正式版本；界面区分“保存中”“已保存”“保存失败”。
- 自动保存不把其他人的新版本覆盖掉；版本冲突保留当前草稿，提供查看差异和重新合并入口。
- 预览复用阅读渲染器。媒体失败提供原位置重试，失败上传不能留下假图片节点。
- 第一版不做拖拽页面布局、数据库表格、无限嵌套组件或多人实时编辑光标。

### 4.6 时间线

```text
时间线     [全部 Tag v] [年份 v]

2025 年
  05 月     某次露营的故事          [聚会] [事件]
  日期未详  这一年的另一件事       [重大事件]

2024 年
  10-06     一篇有准确日期的文章    [事件]

[查看尚未填写发生时间的文章]
```

发生时间与创建、更新时间分别保存。支持年、月、日三种精度；只知道年份时显示年份，不虚构月日。无发生时间的文章在普通列表可见，通过单独入口补日期，不用更新时间填充时间线。

全站时间线和 Tag 时间线共用查询与组件。时间筛选、Tag 筛选和排序保存在 URL 中，可刷新和分享。时间跨度较大时分段加载。

+-------------------------------+

+-------------------------------+
| 文章标题                      |
| [人物] [某个主题]             |
| 更新信息                      |
|                               |
| 正文、图片、引用……           |
|                               |
| [视频封面与播放按钮]          |

手机优先呈现正文；桌面右侧栏移到标题附近和正文末尾，侧栏导航收进菜单。图片可放大，视频可全屏，编辑工具栏滚动时保留可访问入口。页面在 360px 宽度不能横向溢出；引用中的长链接可换行。

### 4.8 搜索与版本状态

搜索提供关键词、Tag 筛选和结果数量，标题优先，其次正文。输入中文拼音时等待输入法组合完成再触发请求。支持两字昵称和连续中文子串，匹配片段使用纯文本高亮。

版本页展示修改者、时间、修改说明和正文差异；图片、视频、Tag 与发生时间变化以变更清单展示。恢复旧版生成一个新版本，历史记录保持可追溯。

## 5. 内容与存储模型

“只有文章和 Tag”指核心业务模型，不代表数据库只能有两张表。版本、媒体和账号是支撑能力，不引入新的内容类型体系。

### 5.1 核心表

| 表 | 关键字段与约束 |
| --- | --- |
| `articles` | 稳定 `id`、`title`、正文 JSON、`schema_version`、派生纯文本、发布状态、当前版本号、作者、创建与更新时间、可选发生时间及精度、软删除时间 |
| `tags` | 稳定 `id`、名称、名称规范化键、说明、是否进入导航、导航排序；规范化名称唯一 |
| `article_tags` | `article_id + tag_id` 唯一，支持双向查询 |
| `article_versions` | 标题、正文、Tag 名称与 ID、发生时间的完整快照；编辑者、修改说明、版本号、创建时间 |
| `article_drafts` | 用户、目标文章或新文章 ID、草稿内容、基础版本号和更新时间 |
| `article_links` | 从当前已发布正文派生的源文章、目标文章、段落 ID，用于反向链接 |
| `media` | 媒体 ID、上传者、存储驱动、对象键、实际大小、校验信息、类型、状态、可选宽高与播放信息 |
| `article_media` | 文章或版本与媒体的关联，支持权限校验与安全清理 |

账号、会话、邀请、上传任务和迁移状态按各自模块保存。没有 `Person`、`Event`、`Topic` 和通用属性值表。普通标签名称不触发隐藏权限或自动发布规则。

### 5.2 正文格式

正文以受控富文本 JSON 为唯一可编辑来源，纯文本与阅读视图为派生结果。顶层保存 `schema_version`，节点有稳定 ID；内部文章链接保存目标文章 ID，媒体节点保存 `media_id`，不把临时签名 URL 写进正文。

客户端和服务端都验证节点类型、深度、正文大小和链接协议。服务端是最终校验边界。阅读器按受支持节点输出元素，不直接执行用户提供的 HTML。

提供 JSON 与媒体清单的完整导出，同时提供便于阅读的 Markdown／HTML 导出。Markdown 导出不承诺无损表达所有未来富文本扩展；恢复使用完整导出包。

### 5.3 时间与写入一致性

发生时间保存规范化日期值和 `year / month / day` 精度。排序所需的补齐日期仅作内部排序键，展示仍遵循原精度。创建、更新时间使用 UTC 时间戳，按站点时区展示。

文章发布、版本记录、Tag 关联、媒体关联与反向链接更新在一个数据库事务中完成。写请求携带 `expected_revision`，发现版本不一致返回 `409 REVISION_CONFLICT`。Tag 改名不会断开文章链接，文章重命名不改变 ID。

新文章保存草稿时先分配文章 ID，基础版本为 `0`，只有作者可见。已有文章的草稿按“用户 + 文章”保存，保留开始编辑时的基础版本；自动保存不修改已发布正文和版本号。首次发布生成版本 `1`，以后每次发布递增版本，并清除本人的已发布草稿，其他作者的草稿继续保留并在发布时检查冲突。

### 6.2 静态资源与开发调试

开发时运行 Vite 和 Go 两个进程，由 Vite 将 API 与媒体请求代理给 Go；生产时仅运行 Go。Vite 产物嵌入发行文件，Node.js 留在构建环境。

| 请求 | Go 处理方式 |
| --- | --- |
| `/`、已知网页路由 | 返回 Vue 入口 HTML |
| `/assets/*` | 返回嵌入资源，带内容哈希的文件使用长期缓存 |
| `/api/v1/*` | 返回业务 JSON，错误不回退成 HTML |
| `/media/:id` | 校验权限；本地模式流式响应，OSS 模式跳转到短期签名地址 |
| `/healthz`、`/readyz` | 存活与数据库就绪状态，不暴露配置 |

不存在的资源返回 404；仅已识别的客户端页面路径使用 SPA 回退。HTML 使用可更新的缓存策略，发布新版本后不能长期引用失效的旧资源。

验证步骤覆盖深链接刷新、浏览器前进后退、中文 URL 参数、媒体请求与静态资源缓存。桌面与手机使用同一组虚构示例数据，比较首页、Tag 页、文章、编辑器、时间线和上传状态，检查设计是否仍保持 Matterwiki 的简单阅读顺序。

## 7. 图片与视频

### 7.1 部署与驱动

`local` 模式将媒体放在数据目录，适用于单机试用和自托管。`oss` 模式存放在独立对象存储中，Go 仅保存媒体元数据并管理授权。业务正文始终通过媒体 ID 引用对象，允许后续迁移存储位置。

实际生产部署采用单独服务器运行 Go、OSS 保存媒体的组合。两者不要求同一云服务商，不能假设部署服务器能访问 OSS 内网 Endpoint。

### 7.2 上传流程

```text
网页 / 小程序                 Go                       OSS
      |                        |                         |
      | 请求上传意图           |                         |
      +----------------------->| 校验身份、类型、配额     |
      |                        | 创建 pending 媒体记录   |
      |<-----------------------+ 返回短期上传授权        |
      |                        |                         |
      +------------------------------------------------->|
      |                 直接上传文件                     |
      |<-------------------------------------------------+
      |                        |                         |
      | 通知上传完成           |                         |
      +----------------------->+------ 校验对象 --------->|
      |                        |<------------------------+
      |                        | 固化对象并标记 ready    |
      |<-----------------------+ 返回媒体 ID 与状态       |
      |                        |                         |
      | 发布含媒体 ID 的文章   |                         |
      +----------------------->| 校验归属并保存文章关联   |
```

OSS 支持服务端签名后由客户端直接上传，可减少文件经应用服务器中转的带宽消耗。[OSS 服务端签名直传](https://help.aliyun.com/zh/oss/user-guide/obtain-signature-information-from-the-server-and-upload-data-to-oss)

上传授权限定随机对象键、有效期和可执行动作。对象先进入临时上传区；Go 在完成阶段校验实际大小、内容类型、文件特征和归属，随后固化到客户端无写入权限的最终对象键。校验和固化之间须使用条件校验，避免已检查文件被替换。客户端报告成功不等于媒体可发布。

上传归属与共同编辑分别处理：新媒体只能由上传者或明确授权者认领；编辑既有文章时，可以保留该文章已经关联的媒体。知道某个媒体 ID 不代表有权把它加入另一篇文章。

小文件使用短期签名上传；大视频按需使用分片上传，Go 管理上传会话与完成校验。API 返回上传方式和需要的字段，客户端不持有长期云密钥。本地模式复用同一意图／完成协议，由 Go 流式接收文件，禁止整段视频一次性读入内存。

### 7.3 展示与资源限制

| 项目 | 第一版设计 |
| --- | --- |
| 图片 | JPEG、PNG、WebP、GIF；保留原图，列表优先使用缩略图 |
| 视频 | 支持 MP4、WebM、MOV 文件上传；以内嵌播放器支持的实际编码决定能否播放 |
| 播放基线 | 验证 MP4 的 H.264／AAC 示例在主流桌面、手机和微信环境播放；MOV、HEVC 等不能仅凭后缀承诺兼容 |
| 格式回退 | 不支持内嵌播放时展示下载入口与格式说明，不显示假播放成功状态 |
| 初始限制 | 图片 20 MiB、视频 200 MiB；均为可配置初值，界面提前展示 |
| 并发 | 单客户端初始最多 2 个并行上传，图片处理后台限并发与像素量 |
| 读取 | 视频支持 Range、拖动进度及全屏；媒体临时授权到期后重新申请 |
| 转码 | 第一版不自动运行 FFmpeg 或云转码任务；按真实格式需求另行评估 |

媒体读取继续校验文章访问权限，Bucket 默认私有。Go 可以返回短期签名读取地址，实际图片、视频字节由 OSS 传输；这与 Go 提供网页静态资源并不冲突。签名地址具有有效期内的持有者访问能力，不能承诺撤权后立即失效。

对象存储 CORS、媒体域名、HTTPS 和允许的请求方法按最终客户端配置。自定义媒体域名是可选项，具体资源值不进入本 RFC。

未完成上传及残留分片定期清理；草稿、已发布文章和保留历史版本引用的媒体都不能当作孤儿删除。删除文章先进入回收站，物理媒体清理在保留期后执行。

## 9. API 契约

API 前缀统一为 `/api/v1`，通过 OpenAPI 描述字段、权限、分页、错误和内容节点。API 不依赖 Vue 页面生命周期，为未来小程序保留独立客户端能力。

| 接口 | 作用 |
| --- | --- |
| `GET /articles` | 搜索、Tag 交集筛选、更新时间排序、发生时间筛选 |
| `POST /articles` | 创建文章并发布，或按状态创建草稿 |
| `GET /articles/:id` | 文章、可读内容及当前版本号 |
| `PUT /articles/:id` | 携带基础版本号更新并发布 |
| `DELETE /articles/:id` | 软删除 |
| `POST /articles/:id/restore` | 恢复回收站文章 |
| `GET /articles/:id/versions` | 可访问的版本列表 |
| `GET /articles/:id/versions/:version` | 版本内容 |
| `POST /articles/:id/versions/:version/restore` | 将历史快照恢复为新版本 |
| `GET /articles/:id/backlinks` | 权限过滤后的反向链接 |
| `GET /drafts`、`GET /drafts/:article_id` | 当前用户草稿列表与内容 |
| `PUT /drafts/:article_id`、`DELETE /drafts/:article_id` | 自动保存或丢弃本人草稿；新文章先通过 `POST /articles` 分配 ID |
| `GET /tags`、`POST /tags` | 查询与创建 Tag |
| `GET /tags/:id`、`PATCH /tags/:id` | Tag 说明与导航配置 |
| `DELETE /tags/:id` | 管理员确认后移除 Tag，不删除文章 |
| `GET /timeline` | 按发生时间排列，可带 Tag 筛选 |
| `POST /media/uploads` | 创建上传意图，返回媒体 ID 和上传描述 |
| `POST /media/uploads/:id/complete` | 服务端校验并完成上传，可幂等重试 |
| `DELETE /media/uploads/:id` | 取消未完成上传 |
| `GET /media/:id` | 查询媒体状态与可用展示信息 |
| `GET /me`、`POST /auth/login`、`POST /auth/logout` | 最小账号与会话能力 |

上述表中的媒体 API 返回 JSON；顶层 `/media/:id` 是供浏览器播放或下载的入口。

列表默认每次 20 条、上限 50 条，使用稳定排序和游标，不一次返回全站正文。发生时间筛选保留日期精度。搜索、列表、Tag 计数、时间线与反向链接使用一致的授权条件。

写入错误使用稳定错误码，至少覆盖 `VALIDATION_ERROR`、`UNAUTHENTICATED`、`FORBIDDEN`、`NOT_FOUND`、`REVISION_CONFLICT`、`UPLOAD_TOO_LARGE`、`MEDIA_NOT_READY` 和 `RATE_LIMITED`。响应可带请求 ID，不能返回密钥、内部文件路径或长期云签名。

## 10. 登录、成员与权限

账号和文章分离。带“人物”Tag 的文章可以没有对应登录账号；账号绑定人物文章是可选关联，不能凭文章同名自动认领。

第一版以管理员初始化和邀请成员为主，提供可在无外部服务时运行的本地登录方式。初次启动生成一次性设置凭证，不开放无凭证抢先创建管理员的入口。管理员、编辑者、阅读者三种角色足够：编辑者可共同维护已发布文章，个人草稿只对本人及明确授权的管理操作开放。

网页使用安全的 HttpOnly 会话 Cookie，修改请求检查 CSRF／来源；小程序使用独立传递的本系统会话凭证，两者经过同一权限层。微信登录不能自动证明用户属于某个微信群。

后续身份绑定表记录用户、身份提供方、提供方作用域和外部稳定 ID；邮箱与手机号需要验证所有权。绑定要求已登录并完成新身份验证，发现身份已属于其他账号时走显式冲突处理。解绑后至少保留一种可用登录方式。外部登录密钥只存在服务端。

## 11. AI 扩展

第一版可以完全关闭 AI。扩展时先实现推荐 Tag 与推荐内部文章链接，直接复用现有文章和 Tag，不改变人工正文。

```text
文章发布
   |
   v
记录“文章 ID + 版本号 + 分析类型”的任务
   |
   v
合并短时间内的更新，按额度执行
   |
   v
生成建议 + 原文段落依据
   |
   v
群友接受 / 修改 / 忽略
   |
   v
通过正常写入流程生成新版本
```

建议绑定源版本；文章已变化时标记过期，不能直接覆盖新内容。原文是事实记录来源，AI 结果是派生索引或待确认建议，可重建、撤销和停用。

AI 调用按站点设置预算与并发上限，密钥在后端；只有被允许提交的内容进入模型调用，检索与问答遵循相同阅读权限。图片识别和视频理解不默认随上传触发。

## 12. SQLite 与资源目标

默认架构是单实例、读多写少的 Wiki。SQLite 适合这类部署，但 WAL 模式仍然只有一个并发写入者。[SQLite 适用范围](https://www.sqlite.org/whentouse.html)、[WAL 文档](https://www.sqlite.org/wal.html)

- 数据库置于本地持久磁盘，启用外键、适当的忙等待和 WAL 管理；不把 WAL 数据库放到跨主机网络文件系统。
- 写事务保持短小，图片处理、OSS 请求、AI 调用在事务外执行。
- 第一版中文搜索使用参数化子串查询覆盖短昵称，并优先匹配标题；FTS 作为测量后的优化，不直接假定默认分词适合中文。
- SQLite trigram 全文查询对少于三个字符的查询有限制，不能用它替代两字昵称的验收。[FTS5 文档](https://www.sqlite.org/fts5.html)
- 编辑器、管理页和后续图谱组件按需加载；阅读页面不加载完整编辑器。采用路由拆包与稳定的列表更新。[Vue 性能指南](https://vuejs.org/guide/best-practices/performance.html)
- 原视频不在首页预加载，媒体不进入 Go 堆内存缓冲；后台任务有并发、超时和重试上限。

首轮验证环境为 1 核、1 GiB 内存、持久磁盘；使用合成的一万篇文章、多个 Tag 和媒体元数据测试列表、中文搜索、保存及后台任务共存。记录空闲／峰值内存、CPU、响应时间和冷启动首屏，不把这些设计目标表述为已测容量。

如果出现持续写入争用、需要多实例或高可用，再提出 PostgreSQL 迁移 RFC。当前不同时维护两套数据库实现，不要求 Redis、Elasticsearch 或 Neo4j 才能启动。

## 13. 启动、配置与备份

发行包包含与平台匹配的 Go 可执行文件和嵌入网页资源，配置与数据在程序外。构建后可使用以下命令，导入默认先预演，实际写入须显式加 `--apply`：

```text
wiki serve --data-dir ./data --listen 127.0.0.1:8080
wiki backup --output ./backups
wiki restore --input ./backups/backup-file
wiki import-matterwiki --input ./legacy-export
```

首次启动自动完成本地数据目录和数据库初始化，随后通过一次性凭证创建管理员。发布提供单容器示例，数据目录必须挂载为持久卷。域名和 TLS 可由部署平台入口或反向代理提供，不作为第二个应用服务。

公共配置只声明 `DATA_DIR`、`LISTEN_ADDR`、`BASE_URL`、`STORAGE_DRIVER`、`OSS_REGION`、`OSS_BUCKET`、`MEDIA_BASE_URL` 等通用键名。真实值、CLI profile、云资源清单、部署地址、日志和密钥由本地忽略目录及部署平台秘密配置管理。公开示例不包含真实资源标识。

SQLite 在线备份使用 Backup API 或 `VACUUM INTO` 等一致性机制，不能在运行中只复制主数据库文件而遗漏 WAL。[SQLite 备份文档](https://www.sqlite.org/backup.html)

备份由数据库快照、正文格式版本、媒体清单、媒体校验信息及恢复说明组成。本地驱动还需备份实际媒体；OSS 驱动需提供媒体保留或独立复制策略，只有对象键清单不足以恢复被删除的文件。制作备份期间暂停物理清理，完成后在空目录执行恢复演练。

数据库升级前先备份，结构迁移失败则停止启动。回滚方案包含匹配版本的程序与数据库备份，不能假定旧程序可以打开新结构。应用日志默认不记录正文、令牌、上传授权和完整签名 URL。

## 14. 旧站与当前仓库迁移

Matterwiki 的 API 包含文章、主题和文章历史，可作为导入接口依据；实际迁移根据授权导出或数据库快照完成。[Matterwiki API](https://github.com/Matterwiki/Matterwiki/blob/master/API.md)

| 旧内容 | 新系统 |
| --- | --- |
| 主题 Topic | Tag；旧主题描述转成 Tag 说明 |
| 文章 | 统一文章，保留原正文与来源标识 |
| 编辑者 | 作者署名或成员映射；不要求导入者拥有可用登录凭证 |
| 历史版本 | 保存原时间、修改者和可获得的内容快照 |
| HTML 或纯文本 | 转为受支持富文本节点；不能转换的片段报告并保留原始导出 |
| 图片、附件 | 导入媒体并重写引用，校验文件数量与可访问性 |
| 旧文章 ID | 保存来源系统与旧 ID 映射，导入可重复执行且不重复创建 |

旧站 hash 路由的片段不会发送到服务器。若要保持旧链接，需要在原入口保留可解析旧 hash 的过渡页面或客户端重定向逻辑，不能只依靠 Go 的 HTTP 301。

导入先预演，输出数量、丢失字段、失败附件和重名报告；这些真实数据报告保存在私有本地目录。迁移后逐类抽查文章、Tag、编辑者、时间和历史版本。发生时间没有可靠依据时留空。

当前仓库的 Next.js、Prisma 和 React 页面作为旧实现参考。新实现按 Go 与 Vue 建设，复用需求与可迁移内容，认证和接口按目标契约重新接通。旧代码仅在新系统验收和迁移验证完成后再归档或移除。

## 15. 实施阶段

| 阶段 | 产物 | 完成条件 |
| --- | --- | --- |
| M0 页面与契约 | 页面低保真、设计变量、正文格式、OpenAPI、Go 承接 Vue 的最小壳 | 桌面／手机导航通顺，深链接可刷新，API 错误不返回网页 |
| M1 文章与 Tag | 编辑器、草稿、发布、Tag 页、搜索、时间线、版本、内部链接 | 人物和事件仅通过 Tag 表达，完整读写闭环可用 |
| M2 媒体与发布 | 图片视频、本地／OSS 驱动、权限、备份恢复、迁移工具、发行包 | 上传播放与权限验证通过，迁移抽查和恢复演练通过；构成第一版 |
| M3 AI 辅助 | 建议 Tag、文章链接及出处，增量分析 | 不改变原文，建议可确认、撤销、过期和限额 |
| M4 小程序与登录 | 小程序阅读与补充，微信／手机号／邮箱绑定 | API 复用，真机上传播放通过，身份绑定与权限一致 |

阶段内先完成阅读与编辑主路径，再处理边缘状态；每阶段保留可运行产物。新增复杂模块必须说明其如何改善真实的群 Wiki 使用，而不是仅增加配置能力。

## 16. 第一版验收

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 新建文章 | 标题与正文即可发布；可选多个 Tag；列表和详情一致 |
| A02 | Tag | 新建后自动有页面；不进入导航时仍可访问；改名不丢文章 |
| A03 | 页面风格 | 首页、列表、正文沿用简单阅读结构；360px 与桌面可用，无虚构统计 |
| A04 | 手机编辑 | 中文输入法、图片粘贴或选择、草稿恢复和发布可用 |
| A05 | 图片视频 | 有进度、失败重试、完成校验；受支持视频可播放和拖动；不支持编码明确回退 |
| A06 | 时间线 | 发生时间与更新时间分离；年／月／日精度不失真；未填日期不被伪造 |
| A07 | 中文搜索 | 两字昵称、连续中文、Tag 交集和无结果状态正确 |
| A08 | 版本与冲突 | 两人编辑产生冲突提示；恢复旧版生成新版本；旧版媒体仍可访问 |
| A09 | 文章引用 | 重命名目标后链接仍有效；反向链接正确；不可读文章不泄露 |
| A10 | 部署 | 无 Node.js 运行时可启动发行包；同一 Go 服务提供网页与 API |
| A11 | 媒体授权 | 私有对象不能匿名绕过；他人的上传意图不能认领；重试不重复发布媒体 |
| A12 | 备份迁移 | 在空目录恢复后文章、Tag、版本及媒体完整；重复导入无重复文章 |
| A13 | 资源 | 在约定的小实例环境报告内存与响应表现，无全量加载原视频或无界后台任务 |
| A14 | 公开仓库 | 提交内容不含真实云资源、凭证、生产导出及本地部署记录 |

验证以影响行为的用例为主：领域逻辑和权限测试、数据库事务与迁移集成测试、媒体驱动契约测试、浏览器关键流程与手机真机检查。后续小程序使用同一 API 契约测试，再增加客户端真机验证。

## 17. 开发前需要收敛的细节

以下不改变“文章 + Tag、Go + Vue、单实例、小程序共用 API”的主体决定：

1. 确认最终站名、标识与预置 Tag 文案。
2. 确认单文件目标平台，以及 SQLite 驱动、FTS 构建与备份能力。
3. 用真实设备测试常见图片和视频格式，确认格式回退与上传大小初值。
4. 在私有配置中确定服务器持久盘、OSS 地域、媒体访问地址、配额与备份位置。
5. 取得旧站授权导出，核对历史版本和附件是否完整。
6. 后续登录阶段再确认微信账号资质、小程序配置、邮件与短信提供方。

公开 RFC 记录通用决策、接口和验收标准；与实际部署有关的结果留在本地忽略目录。
